# M2 Tracker 模块使用文档

Tracker 将每帧雷达质心关联成连续航迹，输出估计位置、速度和不确定度，供导航和
状态判断使用。它不生成飞控指令。

## 输入与输出

| 方向 | ROS 话题 | 消息类型 |
|---|---|---|
| 输入 | `/radar/centroid` | `uav_tracking/CentroidArray`，元素为 `geometry_msgs/PointStamped` |
| 输出 | `/radar/tracks` | `uav_tracking/TrackArray`，元素为 `uav_tracking/Track` |

每条 `Track` 的含义：

- `id`：节点本次运行中的航迹编号；同一航迹持续关联时保持不变，重新建轨会分配新 ID。
- `age`：航迹经历的处理帧数；新建为 1，正常推进时递增，包括未匹配帧，不是秒数。
- `position`、`velocity`：估计的三维位置和速度；`covariance` 是展平的 6×6 协方差。

## 如何启动与验证

在项目根目录加载已构建的 ROS Noetic 工作区：

```bash
source /opt/ros/noetic/setup.bash
source catkin_ws/devel/setup.bash
```

推荐先运行独立 master、临时 ROS_HOME、独立节点名及全部话题重映射的隔离验证：

```bash
bash test/tracker/e2e_test/run_e2e.sh
```

只启动 Tracker 节点时，在专用测试 ROS master 环境中执行：

```bash
roslaunch uav_tracking tracker.launch
```

该 launch 只加载 Tracker 与 `tracker.yaml`，不提供输入数据，也不启动其他控制节点。
上游需要持续提供质心数组，无目标时也应发送空数组。已有共享 ROS master 时，先
使用隔离脚本验证，避免影响同名节点。默认参数见
[tracker.yaml](../../catkin_ws/src/uav_tracking/config/tracker.yaml)。

## 空量测、断流与恢复

- 每收到一帧数组执行一次预测、关联和更新，并发布一帧航迹；没有独立发布定时器。
- 空数组仍触发预测和未匹配计数。默认保留前 5 帧未匹配航迹，第 6 帧删除；无航迹时发布空数组。
- 完全断流时没有回调，不预测、不发布，也不会按秒删除缓存。
- 恢复时按距上次回调的完整 ROS 接收时间差推进。预测仍在关联门限内时可保持 ID；
  航迹已删除或预测偏差过大时会新建 ID。

`TRACKER_RATE_HZ=30.0` 仅决定第一帧默认步长，不要求输入或输出固定 30Hz。
接收时间包含传输和回调调度抖动；生命周期按帧计数，不同输入频率对应的保留秒数不同。
仿真目前假设雷达坐标与 local ENU 数值重合，机载雷达和真机外参属于后续工作。

以下引用已有内部记录，本次文档整理未重新运行测试：完整 pytest `193 passed`，
`catkin_make` 成功。Tracker 隔离 E2E 记录稳定 ID 为 0、`age=1..24`，覆盖有效量测、

这些是算法和隔离 ROS 接口验证，不代表飞行验证。隔离脚本不启动 control_mux、
state_machine、MAVROS 或 OFFBOARD，不调用飞控服务，也不发布最终飞控 setpoint。
