# 模块 2 实现说明

本文件是本地实现补充，不修改 `design/` 中的 develop 原文。

## 分层与接口

- `code/tracker.py` 只实现六维恒速卡尔曼预测、最近邻关联、航迹生命周期和
  `track_state_to_track()`；不导入 ROS。
- `KalmanTracker` 内部使用 `TrackState`。发布前由
  `track_state_to_track(TrackState) -> Track` 转为 ROS 无关的纯发布类型。
- `catkin_ws/src/uav_tracking/scripts/tracker_node.py` 负责
  `CentroidArray` 拆包、ROS 接收时间计算、纯 `Track` 到 `Track.msg` 装包及
  `/radar/centroid` 到 `/radar/tracks` 的事件驱动发布。
- `catkin_ws/src/uav_tracking/lib/tracker.py` 是指向 `code/tracker.py` 的唯一软链接。

实际调用链为：

```text
CentroidArray -> centroids_from_msg -> KalmanTracker.step
-> predict -> associate -> update
-> TrackState -> track_state_to_track -> Track -> Track.msg/TrackArray
```

相关交付文件还包括 `code/config.py`、`code/datatypes.py`、
`test/tracker/test_tracker.py`、`test/tracker/test_tracker_node.py`、
`test/tracker/e2e_test/` 和 `catkin_ws/src/uav_tracking/config/tracker.yaml`。

## 时间与丢失

节点第一帧使用 `1 / TRACKER_RATE_HZ`，后续使用相邻回调的
`rospy.Time.now()` 接收时间差；有效数组和空数组均推进时间基准。消息自身的
`PointStamped.header.stamp` 只作为量测更新时间传入算法，不参与预测 `dt`。
断流期间不增加定时预测，恢复时一次性使用完整接收时间间隔。重复或倒退的 ROS
时间不调用 `step`，倒退时重建时间基准。

航迹删除仍按未匹配输入帧数执行，未扩大到按秒生命周期或关联算法重构。

## 配置与行为

- `TRACKER_RATE_HZ=30.0` 只提供第一帧默认 `dt`，不创建定时发布器。
- 关联门限为 2m，最大未匹配帧数为 5；航迹保留前 5 帧，第 6 帧删除。
- 过程噪声、量测噪声和初始协方差统一从 `code/config.py` 提供，并可由节点私有
  ROS 参数覆盖。
- 无航迹时仍随输入事件发布空 `TrackArray`。

## 验证边界

单元测试覆盖预测、关联、生命周期、`TrackState -> Track` 转换、空数组恢复、
10/30Hz 接收时间、断流恢复及重复/倒退时间。隔离 E2E 只连接重映射的测试话题，
不连接 control_mux、MAVROS 或飞控链。

已完成的隔离验证包括静态和恒速移动目标、10/30Hz 输入、短段空量测、完全断流
恢复以及 ID/age 变化。接收时间包含 ROS 传输和回调调度抖动；完全断流期间缓存
不会按时间自动删除，恢复时较大的 `dt` 可能导致关联失败并产生新 ID。

本轮收尾验证中，完整 pytest 为 `193 passed`，`catkin_make` 成功；Tracker 隔离
E2E 为 `stable_id=0`、`age=1..24`、空量测 3 帧后恢复并按生命周期产生新 ID。
