# M3 Navigator 模块使用文档

Navigator 从雷达航迹选择目标，以 50Hz 输出目标位置指令；长时丢失时输出当前位置
保持指令。输出是 `/ctrl/radar` 中间话题，本模块不直接连接飞控。

## 输入与输出

| 方向 | ROS 话题 | 消息类型 |
|---|---|---|
| 输入 | `/radar/tracks` | `uav_tracking/TrackArray` |
| 输入 | `/mavros/local_position/pose` | `geometry_msgs/PoseStamped` |
| 输出 | `/ctrl/radar` | `mavros_msgs/PositionTarget` |

节点必须先收到当前位置才会发布指令。位姿输入即使约 30Hz，也会缓存最新值，
由 Navigator 自身定时器以 50Hz 发布。输出保持 `frame=1`、`type_mask=3576`，
只启用位置，忽略速度、加速度、yaw 和 yaw_rate。

## 如何启动与验证

在项目根目录加载已构建的 ROS Noetic 工作区：

```bash
source /opt/ros/noetic/setup.bash
source catkin_ws/devel/setup.bash
bash test/navigator/e2e_test/run_e2e.sh
```

隔离脚本自动提供测试航迹和位姿，使用独立 master、临时 ROS_HOME、独立节点名，
并重映射全部输入输出。它检查目标位置指令、发布频率和上游静默后的悬停。

只启动 Navigator 节点时，在专用测试 ROS master 环境中执行：

```bash
roslaunch uav_tracking navigator.launch
```

该 launch 只启动 Navigator 并加载
[navigator.yaml](../../catkin_ws/src/uav_tracking/config/navigator.yaml)，不启动 MAVROS，
也不提供航迹或位姿。测试时应由独立数据源提供两路输入；共享 ROS master 中先使用
隔离脚本，避免影响同名节点。

## 目标与丢失策略

- 多条航迹选 `age` 最大者；相同年龄选 `id` 最小者。当前位置就是第一版目标航点。
- 非空数组刷新最后有效时间，空数组不刷新。
- 距最后非空输入不超过 0.5 秒：有新鲜航迹时生成位置指令，短时无航迹则重发上一条指令。
- 超过 0.5 秒，无论持续空数组还是上游完全静默，都转为最新缓存位姿的位置保持，
  不再追逐旧目标。没有收到过位姿时不发布伪造悬停点。

0.5 秒是时间阈值，不是帧数，50Hz 不改变它的含义。

## 坐标与使用边界

`/mavros/local_position/pose` 按 ROS local ENU 语义使用。`Track.position` 是上游提供的
world 坐标；在当前仿真“Gazebo world 与飞控 local ENU 原点、朝向一致”的设计假设
下，Navigator 将其作为 local ENU 数值使用。该对齐关系尚未完成隔离联调验证。
节点生成 `FRAME_LOCAL_NED=1` 的 `PositionTarget`，但不手动交换 x/y、不反转 z，
也不做第二次坐标转换。MAVROS 1.19.0 的 `setpoint_raw` `local_cb` 已核实会在收到
`FRAME_LOCAL_NED` 消息时，将 ROS ENU 位置、速度和加速度转换为 MAVLink NED 后下发。
因此，若目标航点或当前位置悬停指令后续经系统控制链送入该插件，转换由 MAVROS
完成；这不是当前隔离验证已覆盖的下发链路。`/mavros/local_position/pose` 回传仍
按 ROS ENU 语义读取。

雷达 world 坐标与飞控 local ENU 的原点、朝向是否一致，不能视为运行时已验证事实。
真机外参和运动补偿需另行标定与设计；更换机载雷达前也必须重新确认这些边界。

M3-01 结论：MAVROS 转换机制已核实，Navigator 当前无需手动 ENU→NED；雷达 world
与飞控 local ENU 的原点、朝向对齐仍待隔离联调确认。

本节点只发布 `/ctrl/radar`，不发布 `/mavros/setpoint_raw/local`。上述启动和隔离验证
不需要启动 control_mux、state_machine、MAVROS 或 OFFBOARD，也不需要解锁或起飞。
