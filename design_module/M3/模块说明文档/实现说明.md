# 模块 3 实现说明

本文件是本地实现补充，不修改 `design/` 中的 develop 原文。

## 纯算法接口

- `waypoints_from_track(track: Track) -> list[Waypoint]`
- `send_waypoint(wp: Waypoint) -> PositionCommand`
- `hover_setpoint(pose: Pose) -> PositionCommand`
- `on_timer(tracks, valid_age, last_cmd, current_pose, hold_timeout) -> PositionCommand`

纯算法只处理 `Track`、`Waypoint`、`Pose` 和 `PositionCommand`，不创建 ROS 消息，
不做真机外参或 ENU/NED 二次转换。`Pose` 来源的 `/mavros/local_position/pose` 按
ROS local ENU 语义使用；`Track.position` 是上游提供的 world 坐标。仅在当前仿真
“Gazebo world 与飞控 local ENU 原点、朝向一致”的设计假设下，Navigator 才将
`Track.position` 作为 local ENU 数值使用，该对齐关系尚未完成隔离联调验证。目标航点
和当前位置悬停路径均不手动交换 x/y 或反转 z。

实际调用链为：

```text
Track.msg -> tracks_from_msg -> Track -> select_track
-> waypoints_from_track -> Waypoint -> send_waypoint -> PositionCommand
PoseStamped -> pose_from_msg -> Pose -> hover_setpoint -> PositionCommand
PositionCommand -> position_command_to_position_target -> PositionTarget
```

多航迹选择 `age` 最大者，`age` 相同时选择 `id` 最小者。当前第一版仅生成目标
当前位置航点，不增加预测航点或真机雷达外参变换。

## ROS 节点适配

`navigator_node.py` 将 `TrackArray` 和 `PoseStamped` 拆为纯类型，将
`PositionCommand` 装包为 `mavros_msgs/PositionTarget`，并在 50Hz 定时器中发布
`/ctrl/radar`。位置指令保持 `FRAME_LOCAL_NED=1`、`type_mask=3576`；MAVROS 1.19.0
`setpoint_raw` `local_cb` 收到该 frame 的消息时，会在下发过程中执行 ROS
ENU→MAVLink NED 转换。若后续系统控制链将此指令送入该插件，转换由 MAVROS 完成；
当前隔离验证未覆盖这段下发链路。节点不手动交换 x/y 或反转 z，也不发布
`/mavros/setpoint_raw/local`，不调用飞控服务。

非空航迹刷新有效时间；短时丢失重发上一条位置指令；超过 0.5s 或上游断流后，
使用最新 `Pose` 生成当前位置悬停。空数组不刷新有效时间。

默认配置为 `NAVIGATOR_RATE_HZ=50.0`、`NAVIGATOR_HOLD_TIMEOUT=0.5s`。
`/mavros/local_position/pose` 的输入频率不决定输出频率，节点缓存最新位姿并按自身
50Hz 定时器发布。

## 验证边界

单元和 ROS 适配测试覆盖目标选择、类型转换、50Hz 配置、掩码和悬停超时。隔离
E2E 使用独立 ROS master、独立节点名及重映射话题，输出结果不代表飞行闭环验证。

仿真阶段仍假设雷达 world 坐标与飞控 local ENU 的数值、原点及朝向重合，但该
对齐尚未通过隔离联调确认，不能写成运行时已实测事实。ROS ENU 到 MAVLink NED 的
下发转换机制已由 MAVROS 1.19.0 `setpoint_raw` 源码与本机安装核实；真机外参尚未
标定，完整 control_mux 仲裁和飞行闭环未验证。M3-01 结论：MAVROS 转换机制已核实，
Navigator 当前无需手动 ENU→NED；雷达 world 与飞控 local ENU 的原点、朝向对齐
仍待隔离联调确认。

本轮收尾验证中，完整 pytest 为 `193 passed`，`catkin_make` 成功；Navigator 隔离
E2E 收到 166 条输出，实测 `50.00Hz`，其中有效目标指令 65 条、悬停指令 101 条。
